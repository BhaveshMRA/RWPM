90## Good Defaults
91 
92- `30fps`
93- `1080x1920`
94- design and review at phone-preview size, not only desktop zoom
95- word pop: `70-130ms`
96- card entrance: `180-320ms`
97- scene transition: `250-500ms`
98- diagram draw-on: `400-900ms`
99- stagger: `2-5` frames
100- prefer `transform` and `opacity`
101- avoid layout-shifting animation properties
102- hold important text still for at least `12-24` frames after entrance
103 
104## Hard Blocks
105 
106- Do not animate `top`, `left`, width, height, or layout flow when a
107  transform can do the same job.
108- Do not use infinite CSS animation loops for Remotion output unless the
109  loop is intentionally deterministic at every rendered frame.
110- Do not add blur, filter, huge shadows, or animated gradients to cloud
111  renders without recording a performance reason.
112- Do not move cards, captions, or diagrams into platform chrome zones.
113- Do not approve motion-heavy output from one screenshot only.
114- Do not use `Math.random()` in Remotion animation. Use deterministic
115  seeded values.
116- Do not allow motion to compete with active captions; if captions are
117  moving, cards and background text should mostly hold.

137## Validation Checklist
138 
139- Motion is tied to the script, beat, or information hierarchy.
140- Remotion code uses `useCurrentFrame`, `useVideoConfig`, `Sequence`,
141  `interpolate`, `spring`, or standard transition primitives.
142- CSS animations are not used as the clock for rendered Remotion output.
143- SVG/HTML/CSS code prefers transform and opacity over layout changes.
144- Values are clamped, timed, or deliberately looped.
145- Captions and important text stay readable at phone size.
146- Representative frames show clean entry, hold, transition, and exit
147  states.
