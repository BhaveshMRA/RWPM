139### Important rules for the incremental workflow
140 
141- **Always load the deck from `/tmp/deck.pptx` at the start of each call
>** — do NOT create a new `Presentation()` except in call #1. 
142- **Always save back to `/tmp/deck.pptx` at the end of each call** (exce
>pt the upload call). 
143- **Each call MUST `print()` at least once** — the runtime treats empty 
>stdout as failure. 
144- **Use the same filename `/tmp/deck.pptx` throughout** — do not rename 
>between calls. 
145- **Hardcode the S3 URI string** in the upload call (sandbox cannot acce
>ss agent variables). 
146- **Do not split a single slide across multiple calls** — always complet
>e one slide per call at minimum. 
147- **For 2+ slides per call**, group logically related slides (e.g., two 
>comparison slides together). Keep total code under ~5 KB per call. 
148- **If a call errors out**, the previous successful saves are still on d
>isk. You can resume from the failed slide.
