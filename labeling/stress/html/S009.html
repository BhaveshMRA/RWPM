38 
39After every modification, run shellcheck on the file. This is not option
 >al — always validate before finishing.
40 
41**Detect the shell type and choose flags automatically:**
42 
43For **bash/sh scripts** (shebang contains `bash` or `sh`):
44```bash
45shellcheck -s bash <file>
46```
47 
48For **zsh files** (`.zsh` extension, or shebang contains `zsh`, or files
 > in `roles/zsh/`):
49```bash

52Zsh exclusions explained:

 >urce paths, especially oh-my-zsh plugins.

 >variables (`ZSH_THEME`, `plugins`, etc.) that shellcheck can't see being
 > consumed.

84## Zsh Function Gotchas
85 
86When editing zsh functions in `roles/zsh/functions.zsh` or `roles/zsh/fu
 >nctions/`:
87 
88- **`[ ]` vs `[[ ]]`**: `[ "$x" == "y" ]` fails in zsh with `= not found
 >`. Always use `[[ "$x" == "y" ]]` in zsh files.
89- **Error return codes**: Error paths in functions must `return 1` expli
 >citly — don't let them fall through with an implicit 0.
90- **File layout**: `roles/zsh/functions/` contains standalone files; `_`
 >-prefixed files are zsh completions (loaded via `fpath`), others are sou
 >rced at shell startup by `functions.zsh`.
91- **Testing functions**: Validate interactively with `zsh -i -c 'funcnam
 >e args; echo "exit: $?"'`
