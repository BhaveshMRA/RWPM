12## Core Concepts
13 
14### Working Copy as a Commit
15 
16Unlike Git, the working copy IS a commit. Changes are automatically snap
>shotted 
17when running `jj` commands - no explicit `add` or staging required.
18 
19### Change IDs vs Commit IDs
20 
21Every commit has two identifiers:
22 
23- **Change ID**: Stable across rewrites (e.g., `kkmpptxz`)
24- **Commit ID**: Hash-based, changes on rewrite (e.g., `abc123def`)
25 
26Use change IDs for references that survive rebases.
27 
28### Revsets
29 
30Revsets are expressions to select commits:
31 
32- `@` - Working copy commit
33- `@-` - Parent of working copy
34- `root()` - Repository root
35- `bookmarks()` - All bookmarked commits
36- `foo..bar` - Commits from foo to bar (exclusive)
37- `foo::bar` - Commits from foo to bar (inclusive)
38- `A | B` - Union
39- `A & B` - Intersection
40- `~A` - Complement
41 
42### Bookmarks (not Branches)
43 
44Bookmarks are named pointers that map to Git branches. They move automat
>ically 
45when commits are rewritten.
