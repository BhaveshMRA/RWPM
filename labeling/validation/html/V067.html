41## Research phase
42 
43After clarifying questions, before proposing approaches, gather outside 
 >context. This is **default-on**: skip only with explicit, justified stat
 >ement.
44 
45### 1. Pick research kinds
46 
47From the menu — trends + discourse, patterns, pitfalls, authoritative ve
 >rification, user-context.
48 
49For brainstorming, the **defaults are: web (trends + discourse) and code
 >base (prior art)**. Add others if the topic warrants — e.g. authoritativ
 >e verification when an external API is in scope, or user-context when pr
 >ior decisions in memory are relevant.
50 
51### 2. Dispatch
52 
53Subagent by default:
54- `Explore` for codebase / prior-art questions ("does this repo already 
 >have something like X?", "what's the convention for Y here?")
55- `general-purpose` for web / discourse / verification ("what's the curr
 >ent best practice for Z?", "what pitfalls do people hit with W?")
56- Run multiple in parallel when the kinds are independent
57 
58Inline only for light-touch research (single grep, memory check).
59 
60### 3. Record findings
61 
62Write 3–5 tight bullets into the spec doc under a new `## Research notes
 >` section. Include load-bearing links/refs and anything considered-but-r
 >uled-out so future-you knows it was checked.
63 
64### 4. Skip protocol
65 
66If skipping, write one line into the spec doc: `Skipped research because
 > <reason>. <Verifiable pointer if applicable>.`
67 
68**Valid reasons:**
69- Trivial scope (typo, comment edit, single-line config)
70- Fresh prior research — same topic in current session OR within last 7 
 >days with verifiable spec/plan pointer. **If the pointer doesn't resolve
 >, the skip is invalid.** (Beyond 7 days, repeat the research even if you
 > remember the prior findings — the landscape drifts.)
71- User explicit — **must quote the phrase** that authorized the skip.
72- Repeat of identical task — **must include a pointer** to the prior suc
 >cessful run.
73 
74**Invalid reasons:** "I think I know", "seems straightforward", "moving 
 >fast", "user wants this done quickly", "already familiar with this codeb
 >ase". If those are tempting, do the research.
