90Use the least powerful model that can handle each role to conserve cost 
 >and increase speed.

 >2 files): use a fast, cheap model. Most implementation tasks are mechani
 >cal when the plan is well-specified.

94**Integration and judgment tasks** (multi-file coordination, pattern mat
 >ching, debugging): use a standard model.

 >le model.

103## Handling Implementer Status
104 
105Implementer subagents report one of four statuses. Handle each appropria
 >tely:
106 
107**DONE:** Proceed to spec compliance review.
108 
109**DONE_WITH_CONCERNS:** The implementer completed the work but flagged d
 >oubts. Read the concerns before proceeding. If the concerns are about co
 >rrectness or scope, address them before review. If they're observations 
 >(e.g., "this file is getting large"), note them and proceed to review.
110 
111**NEEDS_CONTEXT:** The implementer needs information that wasn't provide
 >d. Provide the missing context and re-dispatch.
112 
113**BLOCKED:** The implementer cannot complete the task. Assess the blocke
 >r:
1141. If it's a context problem, provide more context and re-dispatch with 
 >the same model
1152. If the task requires more reasoning, re-dispatch with a more capable 
 >model
1163. If the task is too large, break it into smaller pieces
1174. If the plan itself is wrong, escalate to the human

 >changes. If the implementer said it's stuck, something needs to change.
